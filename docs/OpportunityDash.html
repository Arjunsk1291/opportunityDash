1. Overview

The Opportunity Dashboard is the Avenir operations workspace for tender tracking, bid/no-bid decisions, lead triage, partner and client reference data, BD activity, and admin control. Most users spend their time in the core workspace; only Master/Admin users should touch the system control tabs.

What it does

  • Tracks opportunities, status, values, and pipeline changes.
  • Captures bid decisions, follow-ups, and BD engagements.
  • Maintains partners, clients, and pre-qualification records.
  • Surfaces health, sync, permissions, and audit tooling in the Master Panel.

How to use it

  • Start on Dashboard for the overview, then jump to the relevant workflow page.
  • Use search/filter controls before exporting or editing data.
  • Check role visibility if a page or action is missing.
  • Use Master Panel only when you need admin controls, sync, or audit tools.

2. Shell and Navigation

What it does

  • Sidebar groups the app into Core Workspace and Administration.
  • Top-level routes are role-filtered from the sidebar before the user sees them.
  • The shared shell carries logo, route chrome, and the active page state.

Watch-outs

  • If a page is missing, check role access first, not just the URL.
  • Admin tabs are only available to Master/Admin users.
  • Some actions are page-visible but action-gated behind permissions.
AreaWhat users seeWhy it matters

Top barShell branding, utility actions, and page framing.Confirms which workspace you are in.
Route contentScreen-specific widgets, tables, dialogs, and charts.This is where data entry and review happen.

3. Login and Pending Approval

Login

  • /login is the unauthenticated entry screen.
  • /auth/callback completes the sign-in handoff.
  • Approved users are sent into the shell and then to the landing page.

Pending approval

  • Users who authenticate but have not been approved are held in a pending state.
  • The screen should clearly indicate that the account exists but is waiting on access approval.
  • Users in this state should not expect sidebar navigation to be available yet.

4. Dashboard

This is the executive overview. It summarizes the live pipeline, highlights at-risk work, and gives a quick sense of volume, value, stage mix, and approval status.

Primary controls

  • KPI cards for state and value.
  • Advanced filters for scope, client, lead, group, and date-related review.
  • Pipeline chart and list-based widgets for drilldown.
  • Export and reporting actions for the filtered dataset.

How to use it

  • Set scope first, then inspect the chart and list widgets.
  • Open an opportunity from the table or detail dialog when something needs review.
  • Use the dashboard as the sanity check before exporting or escalating.

6. Opportunities

Primary purpose

  • Main operational register for tender rows.
  • Used to inspect, edit, and reconcile workbook data.
  • Often the source of truth for downstream workflow pages.

Main controls

  • Search grid filters visible rows.
  • Add Entry opens manual creation.
  • Upload Sheet imports workbook data.
  • Export downloads the current table.

Permission gate: viewing is broader than writing. Editing, importing, syncing, and manual updates are limited to higher roles, especially Master/Admin and proposal leadership.

8. Potential Opportunities

This page holds early-stage leads before they are promoted into the main register. It is useful for triage and for spotting matches against live opportunities.

What it does

  • Stores potential leads and context.
  • Supports search and spreadsheet-style review.
  • Lets users compare incoming prospects against current opportunities.

How to use it

  • Review opportunity reference, tender name, and scope link first.
  • Use it as a staging area before moving work into the main pipeline.
  • Watch for duplicate or related records.

10. Partners

The Partners page is the vendor directory. Use it to compare capability, certification, and relationship status across third parties.

Main buttons and filters

  • Search by company and capability terms.
  • Import and export partner data where permitted.
  • Open detail/edit views for a specific vendor.

What to check

  • Services, tech stack, and certifications.
  • Agreement and NDA state.
  • Any relevance score or matching context tied to the current work.

11. Clients

The Clients page normalizes company records and contacts into a single directory that can be searched, grouped, and exported.

Behavior

  • Handles import mapping and header detection.
  • Groups duplicate clusters so records can be cleaned up.
  • Stores contacts as part of the client profile.

Watch-outs

  • Check domain and location normalization before using a client record in workflow decisions.
  • Duplicates usually need human review rather than blind merging.

12. Analytics

Analytics is the strategic lens on the pipeline. It emphasizes movement, history, and reasons behind the current state instead of the day-to-day register.

How to use it

  • Switch time ranges before drawing conclusions.
  • Look for trend changes, stage imbalance, and loss themes.
  • Use it to validate whether the operational pipeline is healthy.

What it answers

  • What changed over time?
  • Which segments are rising or falling?
  • Where did opportunities get lost?

13. BD Engagements

14. Follow-Ups

The Follow-Ups page is a note board for tender-specific actions. It is the page to use when a handoff, reminder, or update needs a durable breadcrumb.

Main flow

  • Create a note.
  • Attach it to the correct tender.
  • Edit or delete when the record changes.

Search behavior

  • Search by tender ref, tender name, client, note body, or updated-by user.
  • Use the result list to jump directly into the relevant record.

15. Master Panel

The Master Panel is the administrative control surface. Only Master/Admin users should see it in the sidebar or act on its controls.

What it does

It centralizes user administration, permissions, data sync, telecast, export templates, diagnostics, audit functions, and backup exports.

How to use it

Open the relevant section first, confirm the environment or token state, then make the smallest change needed. Most controls here are stateful and permission-gated. Backup jobs should run outside the app on a scheduler.

18. Ops Console Notes

What to expect

  • Deployment and service maintenance commands.
  • Certificate renewal or hosting checks.
  • Data sync and health verification helpers.

Operator rule

  • Use the console for maintenance, not routine page editing.
  • Document any change that affects auth, sync, or live data availability.
